# AFUScale · 蓝牙诊断版

基于 [Fatpandac/AFUScale](https://github.com/Fatpandac/AFUScale) 的 iOS 17+ 客户端，为 AFU-WL-TZ-A1 采集原始蓝牙数据，分析候选阻抗字段与秤面 / 阿福 App 体脂率的关系。

## 安装

从本 fork 的 Releases 下载 `unsigned.ipa`，在电脑上使用 [Sideloadly](https://sideloadly.io/) 重签并安装到 iPhone。IPA 没有分发证书，不能直接点击安装。首次使用按系统提示信任开发者、开启开发者模式并允许蓝牙。

诊断功能不需要健康授权。免费签名缺少 HealthKit 权限时，正常同步可使用原有「AFUScale 写入健康」快捷指令。诊断版不输出未经验证的体脂率。

## 采集步骤

1. 关闭阿福 App，避免占用秤的蓝牙连接。让 AFUScale 保持前台。
2. 在主页填写身高、年龄和性别。它们只记录到本机，不会修改秤内用户资料。
3. 打开右上角「控制台」，点击「新建会话」，确保没有红色保存错误。
4. 赤脚站上秤，记录秤面显示的体脂率，收到最终包后等待约 15 秒。
5. 点击「本次测量与标注」，选择时间与体重对应的最终包，填写秤面体脂率、资料、实验条件；然后保存。
6. 先「停止」释放蓝牙连接，再用阿福 App 测量。回到 AFUScale 的历史会话补充阿福数值，写明是否另一次测量、两次时间差和对应体重。
7. 从控制台或会话详情导出 **JSONL 和 summary.txt 两个文件**，发送给分析者。文件含原始数据、设备 UUID 和人工资料，使用样本代号即可，无需真实姓名。

建议先采集一个完整的正常赤脚会话、一个穿袜会话，以及同一用户连续三次赤脚测量。随后再做「阿福修改一个资料参数 → 断开阿福 → 秤面离线测量 → AFUScale 采集」对照。一次只改变身高、年龄、性别或运动员模式中的一项，并记下实际操作。不要把 AFUScale 本地资料变化当作秤内资料变化。

## 实现范围

- 默认进入诊断模式，不自动写健康、不在最终包后主动断开。
- 自动发现目标名或 FFB0 广播（排除 Clone 名称）；记录匹配设备的广播、RSSI 和原始广告数据。
- 枚举全部 GATT 服务、特征及描述符，记录 UUID、实例序号和特征属性。
- 读取支持 Read 的特征，订阅支持 Notify / Indicate 的特征，记录请求、回调、错误和原始值。
- 未知服务、未知特征和解析失败的测量包也进入日志。
- 不发送猜测的业务写入命令；订阅所需的 CCCD 操作由 CoreBluetooth 管理。
- 每条事件包含会话 UUID、递增序号、UTC 毫秒时间和系统 uptime。追加写入并同步到本地文件。
- UI 只显示最近 300 条，但文件与导出保存全部事件。重新打开 App 建立新会话，历史文件仍保留。
- 最终包保存当时个人资料和原始候选 A/B；人工标注绑定会话与最终包事件序号，修改标注会保留旧版本。
- 日志写入失败会显示错误并停止日志写入和蓝牙连接；不把内存事件冒充已经保存。收到中断写入的文件可导出，但不允许继续追加标注。

**这不是阿福 App 抓包器**：iOS 不允许普通应用监听另一个应用的 CoreBluetooth 通信。本日志只覆盖本应用可见的回调，不能获取阿福发给秤的私有指令，也不包含完整 HCI / 空中链路。要分析阿福通信还需额外提供 iOS Bluetooth 日志 / PacketLogger 捕获，或其他端的 HCI 日志。

## 体脂率现状

上游算法为 `1.20 × BMI + 0.23 × 年龄 − 10.8 × 性别值 − 5.4 + 校正值`，男性值为 1，女性为 0。上游校正值固定 1.5，阻抗只作为是否计算体脂率的门槛，没有进入公式。

本版保留解析器用于数据对照，但暂停将上述体脂率写入健康。正常同步只写体重和 BMI。A/B 是否是真正的欧姆阻抗、频率、缩放以及其他字节是否编码体脂率尚未证实。秤可离线显示体脂率说明它具有本地计算能力，并不证明 BLE 包一定包含该结果。复现厂商结果也不等同于提高实际测量准确度。

已知最终包解析（从 0 计数）：

| 字节 | 当前解释 | 验证状态 |
|---|---|---|
| 0–1 | AC 29 包头 | 继承上游 |
| 2 | 02 最终包 | 继承上游 |
| 4–5 | BE16 候选 A | 单位 / 意义未知 |
| 6–7 | BE16 候选 B | 单位 / 意义未知 |
| 10–12 | 最终体重编码 | 上游样本验证 |
| 其余 | 未解码 | 全量保留 |

## 开发与验证

- `xcodegen generate` 从 `project.yml` 更新已提交工程与共享 scheme。
- `swift test` 验证持久化、未知包、跨会话标注、修订、截断恢复与测量 fixture，需要带 XCTest 的 Swift 环境（macOS 完整 Xcode 或 Linux Swift）。
- `xcodebuild -project AFUScale.xcodeproj -scheme AFUScale -destination 'platform=iOS Simulator,name=...' test` 运行原有 iOS 单元测试。
- GitHub Actions `Diagnostics build` 在分支推送时执行核心测试、iPhone Release 编译和 iOS 单元测试，并提供侧载 IPA 构件。
- `v*` 标签触发 Release 工作流：核心测试通过后编译真正的 iPhone arm64 App，打包未签名 IPA 并发布。

自动化验证不能代替真实秤测试。首轮日志用于确认设备实际服务、原始包和连接表现；此版本尚未验证真实秤或解出厂商算法。
